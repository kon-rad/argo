# Observatory evidence API and replay

Observatory 1 provides bounded, authorized evidence windows over existing usage, archive, board and org records, plus a pure replay contract. Observatory 2 adds an optional browser workspace and Usage navigation described below. Enable `observatory` in `MODULES` or the vault's `secondbrain.json` `addons` list. It defaults off. Unattributed file observations extend the existing zen-agent runtime and archive collector, with a forward metadata-column migration. Ordinary shared writes do not establish an exclusive file transition or agent ownership. No new credentials, timers or model calls are required. A separate forward migration records sender provenance at org-message insertion without backfilling history.

## Authorization

All endpoints mount behind the same owner session gate as Usage and Org. Local deployments use the local owner boundary. Board bearer tokens, ingest tokens and knowledge tokens do not grant Observatory access. Queries use the source viewers' existing database pool and effective role, with no role elevation, security-definer calls or RLS changes. A restricted database role sees its visible subset; zero visible rows never proves a source is empty. SQL permission denial returns 403 rather than fabricated empty coverage. Coverage reports the effective role, RLS, table ownership and bypass flags.

Source adapters also require their source module: `usage` for archive, calls and runs, `board` for card events, `org` for messages, and `board` for trusted review-gate attempts. Disabled sources are labelled in coverage and omitted from windows. Detail rechecks the source module and current row visibility. Continuation requests recheck all source rows supporting the export, including boundary state and execution intervals. Exports bind to the authenticated session hash and cannot be shared with a different session. A new login starts a new export.

## API

| GET endpoint | Parameters and result |
|---|---|
| `/api/observatory/coverage` | Required ISO instants `from`, `to`; optional `host`, numeric archive `session`. Returns source ranges, host/runtime groups, row counts, untimed rows, unknown run intervals, effective policy and truncation diagnostics. `session_updated_at` is archive freshness, not process liveness. Per-message observation time and ingestion freshness otherwise remain unknown. More than 200 groups sets `hasMoreGroups=true` and `truncatedGroups=null` because the remaining count is unknown. |
| `/api/observatory/window` | Same range/filter parameters. Returns `version`, half-open `[from,to)` window, boundary state, recorded execution intervals, ordered events, diagnostics, `export`, `total`, `next` and `resolution`. First page is at most 500 events. |
| `/api/observatory/window?export=<token>&offset=<next>&limit=500` | Continue the immutable snapshot. Range and filters cannot change. `limit` is 1 to 500. `next=null` ends pagination. |
| `/api/observatory/events/<encoded-event-id>/observation?export=<token>` | Authorized unattributed snapshot detail. Rechecks owner/export, source modules and current rows, observation metadata, tool/request/result paths and the current parent request. Returns bounded redacted diff and observed hashes with ownership unknown; never a verified write transition. Changed association/source: 409; absent observation/source: 404; raw source above 1 MiB: 413. |
| `/api/observatory/events/<encoded-event-id>/diff?export=<token>` | Deprecated compatibility alias for observation detail, with the same observational semantics and authorization. It does not restore captured/commit write grades. |
| `/api/observatory/events/<encoded-event-id>?export=<token>` | Returns pinned event metadata and an authorized source pointer, including stable row ID and part key. No transcript body, tool arguments, hidden thinking or current card state is returned. Thinking detail may include an existing authorized Codex summary, with explicit hidden/unavailable states. Missing/deleted source rows return 404; denied source reads return 403. |

Ranges must be positive and at most 24 hours. Unknown parameters return 400. Archive JSON transfer is additionally capped at four MiB before expansion. Source reads use a read-only repeatable-read transaction, a three-second per-statement timeout and a 5,000-record cap for each source and expanded result. Oversized results return 413, rather than silently truncating a replay. Query timeout returns 503. Narrow the range or select a session. Archive pairing requires the selected sessions' bounded prior history; a long session can exceed the cap even with a narrow range. A future materialized projection can remove that limitation.

Exports last five minutes, with at most eight exports, four MiB per export and 32 MiB per app instance. Eviction, expiry, process restart and a token belonging to another session return 410 with an explicit restart instruction. Concurrent imports cannot reorder existing pages. Detail validates visibility but returns pinned metadata: it does not pretend that a mutable source body is part of the snapshot. Complete all pages before replaying or exporting locally; `total` is the expected event count. Boundary and intervals repeat on each page.

Host or session filters exclude board, org and review-gate events because those sources have no reliable host/session identity. Filtering does not infer a join through today's roster or an unscoped run string. Coverage labels these limits. Counts describe the caller-visible, requested range only; historical completeness and human-origin coverage remain unknown. Production coverage requires a separate audit.

## Evidence and identity

The public pure module is `@secondbrain/contracts/observatory`. Every event has schema version, canonical ID, source table/row/part, occurred time (UTC epoch milliseconds or null), observation time (unknown unless independently recorded), timestamp precision, source sequence, recorded part index, actor provenance and optional causal reference. Parts at the same timestamp retain their source order; no synthetic milliseconds are invented. Untimed events remain in the event list with null time and never affect replay state.

Archive session identity is `archive:<numeric-session-id>`. Archive context retains host, source, harness and external session ID as separate fields. An execution is `run:<encoded-host>:<encoded-run-id>`, never a persona or conversation ID. A tool occurrence is the archive message part's canonical ID. Tool result pairing is scoped to the numeric archive session and recorded occurrence. A reused tool ID starts a new occurrence. If multiple unmatched calls reuse one identifier, the result stays unpaired. A result needs a recorded matching identifier and noncontradictory known timestamps; unmatched results retain unknown causality. Subagents with their own archive session remain distinct.

Archive events reuse `archive/steps.ts` expansion. Usage rows are separate `usage` events with tokens/model, never extra tool events. Joins use host, source/runtime and external session identity. Archive expansion does not join usage rows, so two calls and two resumed runs cannot multiply one archived operation. Execution attribution requires exactly one containing recorded interval; overlap is left unassigned. No adjacency across machines establishes causality. Org thread and task references are explicit; current roster labels are not historical human provenance.

Prompts remain `actor.kind=unknown` without independently recorded sender provenance. `role=user`, channel text and a current roster runtime do not prove human origin. Org author/channel provenance is retained. New org messages snapshot `author_kind` from the roster in an invoker trigger at insertion; updates cannot rewrite that kind, and changing the author resets it to unknown. Historical rows stay unknown instead of borrowing today's roster. Archive prompts use explicit recorded `sender.kind` (`human`, `agent`, `automation`), with optional `sender.id` and `sender.channel`; roles or channel labels alone remain unknown. Collectors without this metadata remain unknown. Overview thinking events expose availability only. Successful file changes, commit/review/merge facts and hidden reasoning are not reconstructed from token totals, shell text or missing history.

## Replay semantics

`makeWindow` applies only events strictly before `from` to build the boundary. Card state comes from recorded transitions, never `cards.status`. The latest prior state-bearing event establishes each card's initial state. Creation/move payloads, claim, block and explicit finish outcomes are understood. Assignment, reclaim and dependency events whose resulting status is not fully recorded reset the state to unknown. Boundary provenance maps every derived ticket/tool state to its last recorded event, source pointer and occurred time. A card with no prior state remains absent/unknown, even if it is done today.

`replay(window, cursor)` restores a fresh boundary copy, deduplicates canonical event IDs, orders timed events and binary-searches through `cursor` inclusively. Backward and forward seeks return the same semantic state without mutating input. Calls start pending; only a result at or before the cursor can complete them. Source normalizers that do not record success leave the result outcome unknown. The reducer returns ticket/tool state and active executions; event detail stays in the pinned window.

Visibility is exactly `start <= cursor < end` over recorded `usage_runs` execution intervals. Concurrent runs remain distinct. Resumed sessions produce separate intervals and empty idle gaps. Missing, inverted or open interval ends are excluded, not extended to infinity. Conversation archive start/end, import freshness and current persona presence cannot supply execution intervals. Active replay output excludes future end/outcome fields. This version supports historical recorded execution only; current live executions require prospective lease/process capture and are labelled unsupported. A board lease is not automatically equated to a running process.

## Browser workspace (Observatory 2)

With the addon enabled, open **Work > Observatory** at `/observatory`, or **Show activity** in a Usage session. The route and navigation remain absent when the module is off. The workspace uses pinned `three@0.186.1` and `3d-force-graph@1.80.1`, with zero warmup/cooldown physics ticks and deterministic machine/execution positions. Concurrent runs have independent markers. Session and attached edges disappear exactly at the recorded end; idle gaps have no execution marker. Current process liveness remains unsupported by slice 1. “Live history refresh” fetches a fresh recorded window every 15 seconds while the tab is visible, without extending open intervals or suggesting a process is running.

Usage links derive their range and cursor from recorded session start/end and loaded step timestamps. Sessions lasting up to 24 hours include their full known span, including the final instant. Longer sessions open the latest recorded day; use the range form to inspect earlier days. Missing start times use an available recorded end/step, and sessions with no time anchor show an explicit unknown-time label instead of a link. No wall-clock fallback invents evidence.

The URL stores UTC epoch-millisecond `from`, `to`, `cursor`, host, numeric archive session, ticket, runtime, persona, model, origin and selected event. Browser back/forward restores these values. Ranges are limited to 24 hours. Seek, reverse playback and previous/next event use the pure shared reducer. Events at the same instant step together in recorded order. The slider supports keyboard arrows. Labels use the app timezone; the range form accepts UTC ISO instants. Server host/session filters restrict source reads; the other filters apply to the loaded window. Origin filters affect events, leaving recorded execution identity intact. Ticket, persona and model event filters use recorded execution associations even after the execution ends, so past events remain inspectable while markers and edges disappear. A model label requires a usage observation at or before the cursor; it stays unknown beforehand.

Amber diamonds identify evidenced human origin; cyan spheres identify agents; grey boxes identify automation and hollow grey octahedra identify unknown origin. The same glyphs and words appear in the HTML event list and inspector. A prompt role alone never makes a human. Synthetic demo provenance is explicitly synthetic and never mixed with recorded API results. Short tool-call/result markers last two seconds of replay time and point to explicit file targets where available. Return arrows identify results. Structured `read`, `read_file`, `Read`, `write_file`, `Write`, `edit_file` and `Edit` inputs can supply a bounded `path` or `file_path`; the overview path projection discards other arguments and file contents, while authorized raw sources remain content-bearing. Shell command text is never parsed for targets. Every target is an operation attempt, including when a tool reports success, rather than proof of changed bytes.

The execution list, target list, timeline and inspector work without WebGL. Disable “Show 3D workspace” to use only HTML. Context loss or renderer construction failure gives the same fallback. Geometry/material resources, resize observers, interaction listeners and timers are released on unmount; geometry and materials are shared by visual kind/origin and retained across seeks until unmount. Visible meshes are reused by identity; unchanged scenes skip graph replacement. The renderer uses pixel ratio 1, no antialiasing, low-resolution spheres and retains the camera. Rendering pauses after 1.2 seconds without scene/camera interaction, and when the document is hidden. No continuous force simulation or transcript bodies run in the overview.

All immutable pages must arrive before replay. One current snapshot is kept in component memory, with no local storage or multi-window query cache. Loading aborts on range/filter changes and unmount. Event count is capped at 5,000; serialized page transfer accounting is capped at 32 MiB (including repeated boundaries), with explicit errors for incomplete, changed or oversized snapshots. This is a cache/transfer budget, not a measured browser heap ceiling. The display caps at 500 nodes and 1,500 edges and reports omissions; timeline HTML shows the latest 200 timed events through the cursor. Untimed counts and source diagnostics remain visible. Narrow the range for earlier detail.

Source detail is fetched only after **Verify source detail**, rechecking the export and source authorization. Expired/evicted exports and denied sources show errors; restart explicitly. Successful verification offers the existing Usage session URL with the recorded part key. Usage loads up to 50 pages to locate that part, scrolls to its anchor and labels an unavailable part. This destination is the existing authorized source viewer, outside the overview. For thinking events, Verify source detail rechecks source permissions and reads at most one MiB of current source JSON. Only existing Codex `reasoning.summary` blocks of type `summary_text` can be shown as an authorized summary, capped at 20,000 characters and passed through the existing redactor. Encrypted/redacted reasoning without a summary is labelled hidden. Absent summaries, unsupported formats and oversized rows are labelled unavailable. Before verification the state is explicitly not checked. Raw thinking bodies are never substituted for a summary and nothing is reconstructed. Summary bodies stay out of the overview/export and are cleared on selection or snapshot change.

## Prospective code evidence (Observatory 4)

The version 1 replay contract separates write reports, file observations and review-gate receipts. A valid paired result with explicit outcome=success may establish tool-reported-success. Unknown, missing, failed, unpaired or contradictory results cannot establish it. Ordinary shared-worktree writes and edits never establish an exclusive transition: a peer can write between any userspace check and the actual write. This release implements no atomic/exclusive creation exception or enforced isolated-writer boundary. It emits no new details.change or verified captured/commit write grade.

Zen-agent write_file and edit_file optionally return runtime-owned details.fileObservation. These are two observed snapshots, not proof that this tool owned the transition. Metadata contains version, observation ID, opaque repository/worktree hashes, repository-relative path, observedBefore/observedAfter SHA-256, ownership=unknown and diff availability. A missing prior observation is observedBefore=null, which is not exclusive proof that this agent created a new file. The normalizer adds origin=runtime-observation. Legacy details.change records become origin=legacy-reported observations, never retroactively verified transitions; the old change_evidence column remains for compatibility and is not a new write-ownership proof.

Observed source diffs use changed-lines with context=0, redacted=true and numbered added/deleted hunks. Unchanged context is omitted; partial hunks are never labelled a full-file replacement or executable patch. Bounds are 64 KiB per input, 512 lines per input, 4,096 bytes per line and 16 KiB serialized diff. Sensitive changed/deleted lines are replaced in full before result/session persistence, including adjacent same-line code. Best-effort recognition covers credential names, common token/URL forms and known secret process/runtime values of at least eight characters. Recognized private-key blocks, known multiline secrets, invalid UTF-8/binary or size bounds yield hashes with explicit unavailable reason; empty files use empty-change. Legacy bounded replacement source remains separately labelled. Original hashes identify observed bytes before cleaning, not displayed redacted text.

Canonical containment, lstat including dangling/parent symlinks, regular-file and inode checks remain conservative snapshot guards. A final pre-write comparison can suppress an obvious conflicting observation but cannot prove exclusive ownership. Edits require replacement input to match the prepared snapshot for observational consistency. Unsupported files/content over 16 MiB, symlink/path changes, missing Git identity and inconsistent final bytes leave observations unavailable. Tool overwrite/success behavior and private original arguments remain unchanged; an external writer can still race after the final check. No lock, transaction or agent-ownership claim follows from a matching before/after pair.

Pairing requires matching recorded tool names, explicit call IDs and noncontradictory paths. Known Codex, Claude and Hermes protocols may omit result names when no recorded name contradicts the call; unknown nameless protocols remain unpaired. Any explicit structured result path is bounded and must match the call, or its validated runtime resolution; present-invalid or mismatched result paths cannot attribute success, even without observation metadata. No prose, shell text, suffix or guessed cwd establishes a target.

New eligible source results separately include details.captureRequest={path,resolvedPath}; the historical field name does not imply capture or ownership. It binds the exact original argument to a canonical resolved worktree path, enabling ./ and nested-cwd calls. Malformed/null/contradictory presence cannot fall back to legacy matching. Absent binding retains conservative exact repository-relative or worktree-hash-validated absolute matching. Only a validated result can gain target.vaultPath from its explicit resolved path under configured vault root, by copying its target; its earlier relative call stays unresolved. Hunk text and request fields never enter fileObservation overview metadata or the new file_observation column.

The forward metadata migration is 1756000020750_archive-file-observations.sql, after legacy 20700 and before the optional child projection20800. It adds a nullable body-free column without rewriting raw history. Canonical reingestion rebuilds metadata. A valid legacy raw record can be exposed as a legacy-reported observation when it matches the retained legacy metadata; records lacking compatible projections need reingestion rather than invented provenance. New source observations have no change_evidence entry claiming a transition.

Authorized observation detail rechecks the full pinned export, source module/current row visibility, metadata, current tool and request/result/parent association, with the 1 MiB source guard and source redaction. It returns redacted-observation-source, ownership unknown, observed hashes and bounded hunks. Present-invalid or contradictory current binding returns409 even if hashes/diff metadata are unchanged. Optional binding absence follows legacy compatibility: ./ or nested targets needing explicit proof fail when proof is removed, while independently valid canonical-relative/absolute targets can remain readable. No protected diff store or daemon is added.

inspect_change_commit retains its tool name/arguments for compatibility, but compares a stored observation pair with exact parent/commit Git blob contents. commitMatch is a separate local-object content fact with authorship unknown. It neither proves this agent wrote the file nor raises a write grade, and the read-only comparison creates no new write/edit target or map glyph. Observation handles are bounded and current-instance only. PR, review, recorded merge and verified merge receipts remain separate trusted-gate facts, not deductions from file snapshots.

Workspace file identities are per operation/observation, including host, worktree and observation ID. An older content match cannot upgrade a later observation or write report. Legacy claims, runtime snapshots and local Git matches are explicitly labelled in the inspector; unknown outcomes have no observed-diff control. Reverse seeking removes later observations/facts. A read-only content comparison may retain a note association from exact earlier observation context without becoming a new write operation.

Ordinary assistant tool calls and dedicated trace arguments retain write_file.content and edit_file.old/new for resume, including supplied credentials. JSONL and archive raw records remain content-bearing private sources with existing access controls and archive redaction. There is no secret-free trace guarantee. Context-free redacted observation diffs avoid an additional copy of unchanged lines, not all possible private argument content.

| Runtime/source | Evidence | Remaining limits |
|---|---|---|
| Zen structured write/edit | Explicit tool success plus optional bounded unattributed snapshots/hunks | Shared/uncooperative writers prevent exclusive transition proof; ownership always unknown |
| Zen Git inspection | Exact local blob content match against an observed pair | Separate content fact, no authorship/transition/write-grade claim; single parent, current instance |
| Legacy structured change records | Legacy-reported observations with ownership unknown | No retroactive exclusive transition or verified mutation grade |
| Claude/Hermes/Codex archives | Explicit supported attempts/results and structured targets | No inferred byte ownership, shell mutation, missing outcome or guessed cwd |
| Trusted review gate | Observed PR, matching review, recorded merge and prospective verified merge receipt | Only retained caller-visible records; no global historical completeness |

## Brain Map activity (Observatory 3)

Enable both `map` and `observatory` to use **Brain Map replay** from the workspace. On the normal map, **Show activity** opens replay filtered to the selected note, if any. `/map?activity=1` and `/observatory` use the same replay component and URL contract: `from`, `to`, `cursor`, host/session/ticket/runtime/persona/model/origin filters, selected `event`, exact vault-relative `note`, pinned `layout` and synthetic `demo`. Mode links preserve these values. Note clicks filter recorded calls and their paired results. Selecting an execution highlights its evidenced note operations; it does not create an execution interval. Disabling Observatory keeps normal map search, layers, metrics, inspection and kiosk behavior and makes no Observatory requests.

The map loads one stored layout, caches it under its version and pins that version in the URL. `GET /api/map/graph?version=<positive integer>` returns that retained layout, including build time and its original coordinates. The default endpoint still returns the newest layout with its existing ETag. Map builds currently retain three layouts. An expired/missing pinned layout returns 404 and the UI reports it; remove `layout` from the URL and reload to select the newest layout explicitly. Successful write reports with an explicit target appear alongside their attempts only after the result timestamp. Observational snapshots are labelled ownership unknown and do not raise the write grade. Reverse seeking removes the later result/fact before its timestamp. Playback changes a separate overlay group rather than replacing graph data or running forces. Read attempts use a circle (`○ R`); write/edit attempts use a triangle (`▲ W`). Color preserves sender origin across both views: amber for human-attributed records, cyan for agents and grey for unattributed/automated records. Each resolved note also has a keyboard-accessible Focus note control that brings its recorded operations into view. HTML lists provide the same operations, source row/part pointers and note filters. Geometry/material resources for the overlay are disposed on replacement and unmount.

Every map replay labels the layout version/build time and says that current topology is context only. Activity at an earlier cursor does not establish that a current note or link existed then. This is no historical topology reconstruction. Markers represent explicit structured tool-call attempts through the cursor, not changed bytes, authorship, successful writes or live process activity. Recorded operation evidence can remain after execution ends; active execution markers still follow the original half-open intervals.

Path resolution is conservative. The server retains each raw structured tool path. Uncaptured or legacy file calls gain target.vaultPath only from an absolute path beneath the configured vault root, excluding hidden subtrees such as the engine checkout, or a separately verified relative-note contract described below. New Zen write/edit observation results may instead gain scope from a validated runtime-owned captureRequest: the exact original argument and canonical resolved path must agree with the observed worktree/path identity before the resolved path is checked against the configured vault root. This scopes only that observed result; its earlier relative call stays unresolved. Relative paths without this explicit evidence remain repository/path targets even when spelling resembles a note. Hosts with a different vault root remain unresolved unless recorded resolution passes the configured boundary. There is no suffix, basename, case-folded, symlink, guessed cwd or inferred move matching. The browser resolves a scoped path only to one exact kind=note reference in the pinned layout. Missing, deleted, moved, excluded and ambiguous paths remain visible with their source evidence and unresolved reason. Shell text and arbitrary supplied vaultPath assertions cannot establish scope. Map replay performs no filesystem reads, source-privilege expansion or LLM processing.

Structured Codex `function_call` arguments are expanded from the stored payload even when overview text is omitted. `read_note` and `write_note` retain bounded structured `path` attempts with read/write operations. For uncaptured relative note calls, only zen-agent's verified `read_note({ path })` contract (`zen-agent/src/tools/knowledge.ts` calling `GET /api/file/source`) establishes vault scope for canonical keys. Hidden segments, traversal, backslashes, drive prefixes and noncanonical keys stay unresolved under that note-key contract. Other unproven call paths need the configured absolute vault boundary. There is no `write_note` backend implementation or documented relative-path contract in this engine revision, so relative `write_note` attempts remain unresolved. This is separate from the validated Zen `write_file`/`edit_file` observed-result binding above, which can establish scope for `./` and nested-cwd requests. A tool name or arbitrary supplied `vaultPath` field cannot establish scope. Attempts and successful recorded results remain distinct evidence levels.

### Observation detail representation binding

Server normalization adds a body-free `FileObservation.detailDigest`: SHA-256 of the validated, redacted diff representation with recursively sorted object keys and ordered arrays. Runtime observations and legacy reported snapshots both receive this digest before metadata storage/export; raw producer records do not supply it. The authorized lazy endpoint requires the exported digest and current source digest to agree, returning 409 for changed bodies even when observed hashes and diff availability remain identical. Reordering JSON object keys preserves the digest. No hunk or replacement text enters overview metadata. Older runtime-observation projections without this digest require canonical reingestion before detail is available. The existing legacy-column compatibility path may derive the digest while exporting a validated current legacy source. An exported event with a missing or malformed digest fails closed. Current source authorization, parent/request/path validation and the 1 MiB source guard remain required.

The coordinator SQL audit reports `file-observation`, `legacy-change` and `missing` separately by host/runtime, including observation origin and readable/unavailable/unknown diff availability. Legacy-only level is reported separately; these counts describe recorded evidence, not all actual file changes. The migrated scratch regression executes that exact query on one row of each kind.
