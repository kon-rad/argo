# Desk contract desk/v1

Pure browser/server TypeScript. Import from `@secondbrain/desk-contracts/desk` after the workspace package is wired and built. No chain SDK, signer, database or network is included. `fixtures` and `fake*` are synthetic development aids. Production boot must call `assertProductionAdapters('production', adapters)` on every adapter and independently reject fixture configuration. Do not claim a fixture proves a live result.

## Wire and trust rules

`parseRecord` strictly validates the seven versioned record shapes and rejects unknown fields. Entity references are `chain-namespace:chain-id/entity-id`; the reference prefix must equal the record's `chainId`. IDs are opaque, nonempty strings. Times are non-negative integer Unix seconds; quantities are canonical non-negative integer atomic-unit strings, never JSON numbers. Adapters choose and consistently normalize chain identifiers and wallet representations before producing observations. Token decimals, actual transfer interface, supported chains, transaction format, identity ABIs and chain SDKs are deliberately unselected. P6 must validate their current primary documentation and enforce their numeric bounds. Public references support only unencrypted `swarm://` plus 64 lowercase hex characters; key-bearing encrypted references must never be included.

`Observation` is a **trusted adapter assertion**, not a payload or a worker callback. The adapter must independently verify entity reference, immutable creator, chain, inclusion/finality, authoritative chain timestamp, schema and complete pagination. It must not infer creator from a record's wallet field. The reducer checks that assertion against the job client or accepted provider. The nonce scope is `(domain, chainId, authenticated creator, nonce)` across jobs; the adapter must supply the complete finalized nonce history, and orchestration must durably reserve nonces and attempts. A job acceptance is a public entity authored by the job creator. There is no signed-envelope acceptance path in v1; wallet signatures can authorize chain transactions but are not evidence that a transaction executed. Any future off-chain signature path needs its own versioned domain, chain, nonce, expiry, signer recovery and replay design.

Structured digests are lowercase `sha256:` hex over UTF-8 `canonicalJson({domain:'desk/v1', purpose, value})`. Canonical JSON sorts object keys by JavaScript UTF-16 code units, uses JSON string escaping, preserves array order and accepts only safe integer numbers; undefined, non-finite and fractional numbers, bigint, non-plain objects and implicit omission fail. Offer acceptance binds every offer field. `artifactDigest` hashes the exact artifact bytes, without this wrapper. Normalization must occur before hashing and never after acceptance. Implementations outside TypeScript need matching canonicalization test vectors before interoperating.

`reducePublicState` takes a complete, finalized snapshot and a trusted observation time. It sorts by chain time then reference, ignores exact duplicate observations, rejects malformed, unfinalized, future and invalid records, and fails closed on equivocation. Different valid acceptances are conflicting even if discovered after a claim; duplicate identical acceptance payloads select the earliest observation, then reference, and later claims must refer to that selected entity. A nonce reused for different acceptance payloads rejects them. Offer/acceptance and claim must be timely at observation; dispatch additionally checks current deadlines, configured provider, approval digest, cancellation and active attempt. Delivery and payment may arrive after acceptance expires. `unknown` means no authenticated job was established, not an empty successful search. Neither the reducer nor these observations provide atomic locking across operators. Incomplete, failed or stale reads must fail closed outside this reducer. Reservation, concurrency, cancellation and recovery require a durable orchestrator.

Only a trusted settlement verifier can produce `VerifiedPayment`: it independently checks a finalized successful receipt, exact payer, recipient, network, asset, transfer interface, atomic amount, transaction and transfer index, and atomically reserves its unique `receiptId` to one assignment in durable storage. It binds the resulting evidence to `digest('payment-evidence', evidence)`. Never create it from the public payment payload or from a submitted transaction. An unknown or pending transaction remains unpaid. Direct transfers do not provide escrow or nonpayment protection.

Private `Approval` and `WorkerSpec` bind the acceptance digest, skill version, corpus digest, approved input references, execution-plan digest, limits, audience and expiry. `checkWorkerSpec` checks equality, audience and time; it does not authenticate, issue, revoke or enforce a token, execute a sandbox, reserve budgets, or validate the origin of approval. The service must do those things and reject dispatch after cancellation or expiry. Gateway calls must atomically enforce cost and runtime bounds. The worker capability cannot approve, publish, sign or mint capabilities. `checkRelease` compares exact artifact hash, media type and destination alongside revision/idempotency; the publisher must separately verify the bytes, authorization and durable idempotency record. Worker completion by itself creates neither a delivery nor a payment. A provider-authored public delivery alone cannot prove private operator approval; the trusted publisher must enforce that approval before publication.

## Consumer examples

All failures are explicit `Result` variants: `invalid-input`, `denied`, `pending`, `unavailable`, or `failed`. Never turn failed reads into an empty `ok` list.

- **P2 public store/publisher:** `const record = parseRecord(payload); const state = await reducePublicState(observations, jobRef, now);` Authenticate creator and finality before constructing each observation. Call `publisher.publish(claimRef, release, idempotencyKey)` only after trusted release approval; reconcile an uncertain result.
- **P3 orchestration:** `dispatchEligibility(state, {now, approvedAcceptanceDigest, approvedSkillVersion, eligibleProviders, activeAttempt, cancelled})`; enforce an atomic attempt lease and idempotency in storage. `checkMutation(request, revision)` rejects stale actions; `checkRelease(approved, request, revision)` binds publication.
- **P4 worker/gateway:** `checkWorkerSpec(spec, approval, {jobId, attemptId, audience, now, maxLifetimeSeconds})`; independently authenticate the issuer and enforce resource limits. Worker result is private until approved and publicly recorded.
- **P5 identity:** `await identity.resolve(providerId)` returns a `Result<IdentityBinding>` with evidence and a verified flag; a changed profile never rewrites the accepted offer's recipient.
- **P6 settlement:** `await settlement.prepare(intent)` uses the exact accepted `PaymentIntent`; `await settlement.verify(intent, txHash)` must check and reserve the receipt as described above. A testnet/interface is selected only after documentation review.
- **P7 operator UI:** `await operator.job(id)` returns separate `publicState` and private `execution`; submit an `Approval` or `ReleaseRequest` with current `expectedRevision` and unique `idempotencyKey`.
- **P8 client/CLI:** `await client.discover()` and `await client.offers(jobRef)` preserve unavailable/pending errors. `await client.accept(acceptance, key)` publishes an owner-authored acceptance; `await client.independentRead(jobRef)` reads public observations without private account access.
- **P9 integration:** use `fixtures.success`, `fixtures.unverifiedPayment`, `fixtures.conflictingAcceptance`, `fixtures.replay`, `fixtures.invalidAuthor`, `fixtures.expiredOffer`, `fixtures.wrongChain`, `fixtures.cancellation`, `fixtures.changedArtifact`, `fixtures.unknownTransaction`, and `fixtures.rejectedWallet` to exercise error paths; use separately configured real adapters for live verification.

## Changes and tests

`desk/v1` remains provisional until G0 review. Once frozen, any change to wire fields, canonicalization, security semantics, state/adapter interfaces or fixture expectations requires an explicit versioned change note naming affected packages and tests, with lead review before consumers change. Do not copy schemas into consumer packages.

Run `npm test` from the hiring desk package root. The contracts project has no database setup. This package has no runtime dependencies and requires Web Crypto, `TextEncoder`, and BigInt support.
